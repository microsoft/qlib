## 1. 文档边界

本文只整理 Courage 在聊天中明确说过、明确表示自己采用，或明确提出作为候选的技术方案。

本文遵守以下规则：

1. 不使用 2026-08-15 后续冻结合同替 Courage 补充决定；
2. 不把提问者的观点写成 Courage 的决定；
3. 不把聊天中的示例参数扩写成正式合同；
4. 不把收益、胜率、截图和不可读附件当成已核验实验事实；
5. Courage 没有说明的 Label、loss、指标和交易规则统一列为“未说明”；
6. LightGBM 只保留为 Courage 提到的表格模型范式，不设为必经阶段；
7. “未来收益”和“上涨概率”在原话中是“或者”，不扩写为必须同时输出的双任务模型。

## 2. 一句话技术路线

```text
全市场基础行情
  → 过滤不可训练股票
  → 按平均换手率划分数据集并选择目标股票池
  → 清洗目标股票的分钟数据
  → 转换为 Qlib 分钟数据
  → 构造少量、有交易逻辑的分钟级自定义特征
  → 合并上一交易日生成的日频慢变量
  → 滑动窗口生成时序样本
  → 共享 PatchTST backbone + 多 horizon 收益 head
  → 股票打分与排序
  → 交易规则与仓位管理
  → 订单约束检查
  → QMT / PTrade / 券商接口执行
```

## 3. 阶段一：按换手率缩减股票池

### 3.1 Courage 的明确说法

Courage 明确表示：

- 不同换手率股票学习到的模型参数不同；
- 不能把所有股票放在一起训练；
- 应根据换手率对股票或数据集进行分类；
- 可以根据平均换手率把数据集分为几份；
- 再选择自己想交易的换手率区间进行训练；
- 他当时主要交易并训练换手率 5%～15% 的股票；
- 他还提到过一个主要针对换手率 2%～4% 股票的模型；
- 区分不同类型股票时，最简单的维度是换手率和市值。

内部证据：`[E03]`、`[E04]`、`[E10]`。

### 3.2 严格按原话还原的处理顺序

```text
全市场日线/基础行情
  → 计算股票平均换手率
  → 按平均换手率把数据集分组
  → 选择目标换手率区间
  → 提取入选股票的 1 分钟数据
  → 进行后续特征构建和模型训练
```

### 3.3 其他股票池过滤

Courage 还明确提到先过滤：

- ST 股票；
- 退市风险股；
- 长期停牌股；
- 上市时间过短的新股；
- 流动性过低的股票；
- 部分无法正常成交的涨跌停样本。

内部证据：`[E04]`。

### 3.4 Courage 没有说明的内容

聊天没有说明：

- 平均换手率使用多长时间计算；
- 使用全训练区间平均还是滚动平均；
- 验证期、测试期和实盘期如何重新归组；
- 换手率分组本身如何避免使用未来数据；
- 换手率和市值如何共同决定分组边界。

因此，本文只保留“按平均换手率分组并选择目标区间”，不补充具体 PIT 算法。

## 4. 阶段二：清洗并组织分钟数据

### 4.1 原始字段

Courage 给出的 CSV 示例包含：

```text
datetime
symbol
open
high
low
close
volume
amount
```

他还提到资金流等字段。

### 4.2 数据清洗

Courage 明确列出的处理包括：

1. 去重；
2. 时间对齐；
3. 剔除停牌和无成交数据；
4. 处理缺失值；
5. 复权；
6. 过滤异常价格；
7. 过滤异常成交量；
8. 对特征去极值；
9. 对特征标准化；
10. 转换为 Qlib bin 格式。

他倾向于最终使用 bin，而不是直接用 CSV 进行大规模训练。

内部证据：`[E04]`、`[E05]`、`[E08]`。

## 5. 阶段三：把 Qlib 调整为分钟频率

Courage 明确提出四项核心修改：

```text
数据换成 1 分钟数据
Qlib 初始化使用分钟数据目录
特征窗口按分钟定义
Label 预测未来 N 分钟收益，而不是未来 N 天收益
```

同时提到：

```text
DataLoader freq = "1min"
训练集、验证集、测试集按时间切分
```

Qlib 在其描述中的职责包括：

- 数据处理；
- 特征计算；
- 模型训练；
- 预测；
- 回测；
- 策略生成。

实际下单另外连接 QMT、PTrade 或券商接口。

内部证据：`[E04]`、`[E05]`、`[E07]`。

## 6. 阶段四：保证输入在预测时已经可知

### 6.1 Courage 的明确原则

Courage 明确说：

> 10:30 的样本只能使用 10:30 当时已经知道的数据。

盘中样本可以使用：

- 当前及历史分钟数据；
- 上一交易日收盘价；
- 上一交易日成交量；
- 截至上一交易日计算的 MA20；
- 截至上一交易日计算的日频因子。

盘中样本不能使用：

- 当天收盘价；
- 当天完整成交量；
- 当天完整最高价和最低价；
- 当天收盘后才能计算出来的日频因子。

### 6.2 日频慢变量的处理

Courage 最推荐的方式是：

```text
日频特征整体滞后一个交易日
  → 广播到下一交易日全部分钟样本
  → 和分钟数据一起转换成 Qlib bin
```

他给出的字段示例包括：

```text
d_ret5
d_ma20_bias
d_vol20
```

内部证据：`[E06]`、`[E07]`。

## 7. 阶段五：构造分钟级自定义特征

### 7.1 不直接照搬日频 Alpha158/Alpha360

Courage 区分了两类任务：

- 日频选股可以使用 Qlib Alpha158/Alpha360；
- 分钟、分时或 Tick 策略需要基于原始行情构造相应粒度的自定义特征。

他给出的整体结构是：

```text
Tick
  → 1min bar
  → 自定义 feature
  → LSTM / Transformer 预测 alpha
  → 仓位管理
  → 交易执行
```

内部证据：`[E12]`、`[E13]`。

### 7.2 Courage 明确提到的特征方向

包括：

1. 价格行为；
2. 成交量；
3. 成交额；
4. 资金流；
5. 买入金额 `buy_amount`；
6. 均线偏离；
7. 动量；
8. 波动率；
9. 成交量比例；
10. 异常行情状态；
11. 板块指数；
12. 盘口和逐笔数据。

Courage 特别强调：

- 成交量和成交额最重要；
- 异常行情状态可以帮助识别横盘、突破或急速杀跌；
- 分时判断不能只看个股，要横向观察板块；
- 大盘指数不能代替板块指数；
- 板块状态对于判断个股是否“诱多”很重要。

内部证据：`[E13]`、`[E14]`。

### 7.3 特征数量和技术指标

对于“10 个左右特征是否足够”的问题，Courage 的回答倾向于认为不需要太多，并强调：

> 训练模型不能光堆叠因子，要想一下自己是怎么判断股市的。

他不推荐把大量 MA、CDRSI 等通用技术指标作为核心，理由是这些指标仍是分时数据的排列组合，容易过拟合。但他也表示初期可以尝试，以实验观察效果。

因此，按其原话形成的原则是：

```text
先使用少量、有交易逻辑的特征
而不是机械堆叠大量相似指标
```

## 8. 阶段六：构造样本和 Label

### 8.1 表格模型只是被提到的另一种范式

Courage 解释过，如果使用 LightGBM/XGBoost，可以把每个“股票 × 分钟时刻”作为一条样本：

```text
索引 = (instrument, datetime)
特征 = 当前及历史分钟特征 + 当时已知的日频特征
Label = 未来 N 分钟收益
```

这只是对表格模型的说明，不构成“必须先训练 LightGBM”的路线。

内部证据：`[E06]`、`[E08]`。

### 8.2 时序模型样本

Courage 给出的时序样本构造是：

```text
原始行情数据
  → Feature Builder
  → 特征矩阵
  → 滑动窗口切片
  → (samples, time_window, feature_dim)
```

特征矩阵示例：

```text
ret_1
ret_5
ma_bias
volatility
volume_ratio
```

内部证据：`[E13]`。

### 8.3 Label 目标

Courage 明确说：

```text
Label 预测未来 N 分钟收益，而不是未来 N 天收益
```

他给过一个示例：

```text
10:30 产生样本
10:31 买入
11:01 卖出
Label 为这段时间的实际收益
```

聊天没有明确规定：

- 使用 open、close、均价还是 VWAP；
- 是否扣除手续费和滑点；
- 午休、跨日、停牌和无成交如何处理；
- 精确收益公式。

所以该示例不能扩写为正式 Label 合同。

## 9. 阶段七：确定模型预测目标

### 9.1 Courage 提到的候选目标

包括：

- 未来一段时间的相对收益；
- 上涨概率；
- 最大上涨空间。

他的早期完整表述是“相对收益或者上涨概率”，并不是要求两者同时输出。

他更倾向于由模型预测未来结果，再由交易层根据手续费、滑点、波动率和市场状态动态设置盈亏比，而不是把固定止盈止损直接写入 Label。

内部证据：`[E04]`、`[E09]`。

### 9.2 本路线选择的主干目标

后续聊天中最明确、且得到“按照你的思路尝试”响应的是：

```text
共享 PatchTST backbone
  → 分别预测 5 / 15 / 30 / 60 / 120 / 240 / 480 分钟收益
```

因此，本路线把“多 horizon 未来收益预测”作为主干。

上涨概率和最大上涨空间仅保留为 Courage 提到的其他候选，不自动并入当前模型。

内部证据：`[E15]`。

## 10. 阶段八：共享 PatchTST 多周期模型

### 10.1 模型结构

Courage 明确表示，他一般使用：

```text
共享 PatchTST backbone
  → 多个 horizon 输出 head
```

理由是不同预测周期共享底层的：

- 市场状态；
- 量价结构；
- 波动特征；
- 时序表示。

如果数据量足够大，且不同周期的策略逻辑差异明显，再考虑拆为独立模型。

### 10.2 输出 horizon

Courage 明确列举：

```text
5 / 15 / 30 / 60 / 120 / 240 / 480 分钟
```

他表示主要做三天以内的短周期预测；超过三天后，分钟级特征信息衰减明显，倾向于切换日频模型。

### 10.3 输入 lookback

Courage 给出的候选窗口是：

```text
240 / 480 / 960 / 1200 分钟
```

由验证集选择效果最好的窗口。

他说过：

- 输入长度和预测长度是两个独立参数；
- 输入窗口不要求覆盖预测窗口；
- 预测周期越长，一般需要更长的历史上下文；
- 多 horizon 可以共享同一个输入窗口；
- 短长周期差异明显时可以拆分窗口。

候选分组：

```text
短周期 5～60 分钟：使用 240～480 分钟历史
长周期 120～480 分钟：使用 960～1200 分钟历史
```

这些是实验候选，不是聊天中已经冻结的固定窗口。

### 10.4 快慢变量分开编码

Courage 给出的结构是：

```text
分钟动态序列 → PatchTST Encoder ┐
                                ├→ Feature Fusion → 多 horizon heads
日频/静态变量 → Feature Encoder ┘
```

分钟动态输入包括 OHLCV、成交量、资金流、盘口和技术指标等；慢变量包括市值、行业、日线趋势和基本面等。

内部证据：`[E16]`。

## 11. 阶段九：训练与调试

### 11.1 先用小数据跑通

Courage 明确建议：

```text
先用约 2G 小规模数据跑通流程
  → 本地进行小批量调试
  → 云服务器进行大规模训练
  → 训练后的模型在本地使用
```

内部证据：`[E02]`。

### 11.2 数据时间范围和更新

Courage 使用 2026 年数据是为了贴近当前市场风格，但同时认为一年数据的市场周期覆盖仍然偏短，因此提出：

- 后续采用滚动训练；
- 逐渐加入不同市场阶段的数据；
- 防止模型只适应当前行情；
- 每天尾盘接入当天数据微调模型。

### 11.3 训练诊断

Courage 提出的训练方法包括：

- 导出训练曲线；
- 查看 train loss 和 predict/valid loss；
- 导出日志和图像；
- 最终模型不一定采用最后一个 epoch；
- 根据曲线判断过拟合、欠拟合或学习停滞；
- 参数和网络需要逐版实验；
- 设计 baseline，让 AI 输出 KPI 文档；
- 修改前使用 Git 备份；
- 新版本效果好就 commit，效果不好就 revert。

他针对一次具体 LSTM 训练给过 hidden size、层数、dropout、batch size 和学习率建议。这些属于当次日志诊断，不作为通用 PatchTST 参数。

内部证据：`[E04]`、`[E11]`、`[E16]`。

## 12. 阶段十：预测、排序、规则和执行

Courage 最完整的交易链路是：

```text
预测未来收益或概率
  → 对股票打分和排序
  → 根据排名、持仓数量、风险上限、止盈止损和换手限制生成目标仓位
  → 比较当前仓位和目标仓位
  → 产生买单或卖单
  → 检查涨跌停、停牌、可用资金、手续费、滑点和成交量限制
  → 发送至交易接口
```

核心原则：

```text
模型负责预测
规则负责交易
```

模型不直接输出绝对 B/S 点，也不会因为模型看多就直接满仓。

内部证据：`[E01]`、`[E04]`、`[E17]`。

### 12.1 仓位管理的证据边界

聊天中存在两种表述：

1. 规则模块根据排名、持仓和风险限制生成目标仓位；
2. 一张架构草图中出现“RL 仓位管理”。

Courage 没有说明 RL 的状态、动作、奖励、训练数据或实际采用情况。因此：

- 规则式目标仓位是描述更完整的主线；
- RL 只能列为他提到的候选，不能设为必选组件。

## 13. 聊天没有形成决定的事项

以下内容没有被 Courage 明确冻结，本文不补写：

1. 平均换手率的计算窗口与未来数据问题；
2. 精确 Label 价格和收益公式；
3. T+1 的正式处理方式；
4. gross、net 或 excess return；
5. loss 函数；
6. horizon loss 权重；
7. 收益和上涨概率是否必须同时训练；
8. 概率生成和校准方法；
9. checkpoint 的具体选择指标；
10. baseline 的具体模型和指标；
11. ACC、IC、Rank IC 等正式评估合同；
12. PatchTST 的 patch length、stride、层数和 hidden size；

聊天中的“70% ACC 就够了”以及各种胜率、成功率和盈利数字，缺少统一 Label、样本范围、数据切分和基线定义，不作为本路线的验收标准。

## 14. 最终严格版流程

```text
全市场基础行情
  ↓
过滤 ST、退市风险、长期停牌、新股、低流动性和部分不可成交样本
  ↓
计算平均换手率并划分数据集
  ↓
选择目标换手率组（Courage 当时主要使用 5%～15%）
  ↓
获取入选股票的 1 分钟行情
  ↓
去重、时间对齐、复权、缺失值与异常值处理
  ↓
转换为 Qlib bin，freq="1min"
  ↓
构造少量分钟自定义特征
（价格行为、成交量、成交额、资金流、动量、波动率、异常状态、板块指数等）
  ↓
将 T-1 日频慢变量广播到下一交易日分钟样本
  ↓
滑动窗口生成时序输入
  ↓
分钟序列进入 PatchTST Encoder
日频/静态变量进入 Feature Encoder
  ↓
Feature Fusion
  ↓
共享 backbone 预测 5/15/30/60/120/240/480 分钟收益
  ↓
对股票打分和排序
  ↓
规则模块生成目标仓位
  ↓
流动性、风险、成本和成交限制检查
  ↓
QMT / PTrade / 券商接口执行
```

### [E04] 数据、股票池、预测、排序、规则与执行全链路

时间：2026-07-27 17:56  
来源定位：`data/organized/Courage/conversations.md:648-649`

> **Courage 17:56**：数据集有数据集统一的格式，建议参考Qlib的数据集格式。原始数据一般先保存成 CSV，字段包括时间、股票代码、开高低收、成交量、成交额以及资金流等。进入 Qlib 前会做统一清洗，例如去重、时间对齐、剔除停牌和无成交数据、处理缺失值、复权、过滤异常价格和异常成交量，再对特征做去极值和标准化。最终会转换成 Qlib 的 bin 格式用于训练，因为直接读取 bin 的效率比 CSV 高很多。使用 2026 年数据主要是为了让模型更贴近当前市场风格。分钟级数据的样本数量本身比较大，但从市场周期覆盖角度看，一年数据还是偏短，所以后面会采用滚动训练，并逐渐加入不同市场阶段的数据，防止模型只适应当前行情。  
>  
> 股票池覆盖沪深主要 A 股，但会先过滤 ST、退市风险股、长期停牌股、上市时间过短的新股、流动性过低的股票，以及部分无法正常成交的涨跌停样本。我一般让量化玩 5-15 换手率的票，因此只训练了 5-15 换手的，你们可以根据自己来。  
>  
> 模型本身主要预测的是未来一段时间的相对收益或者上涨概率，不是直接预测一个绝对的 B 点和 S 点。例如可以预测未来 5 分钟、30 分钟或者下一个交易周期的收益率，然后对全市场股票进行打分和排序。B 点和 S 点是模型分数与交易规则共同生成的。模型负责判断哪只股票更值得买、预期收益大概处于什么水平；交易模块再结合当前持仓、成交量、波动率、手续费、滑点和止盈止损条件，最终决定是否买入或卖出。所以，并不是模型直接输出BS，而是收益预测—股票排序—交易规则—生成订单一个过程。  
>  
> 具体参数和阈值确实属于策略核心，这部分不太方便完全公开哈哈。不过整体思路可以说：主要看价格、成交量、波动率、量价关系、资金流变化以及不同时间窗口之间的趋势和反转特征。模型给出预测分数后，还会经过流动性、风险、仓位和交易成本等规则过滤，不会因为模型看多就直接满仓买入。  
>  
> 每天收盘后或者盘中实时更新行情数据，数据经过清洗后进入 Qlib，Qlib 根据历史窗口计算因子特征，再由模型预测每只股票未来一段时间的收益并进行排序。之后策略模块根据排名、持仓数量、风险上限、止盈止损和换手限制生成目标仓位。再对比“当前仓位”和“目标仓位”：目标仓位更高就产生买单，目标仓位降低就产生卖单。订单会经过涨跌停、停牌、可用资金、手续费、滑点和成交量限制等检查，最后才发送到交易接口。简单来说，Qlib主要负责数据处理、特征计算、模型训练、预测、回测和策略生成；实际下单则需要再连接 QMT、PTrade 或券商交易接口。我的交易并不是完全凭感觉，也不是模型一预测上涨就直接买，而是模型负责寻找概率优势，规则负责控制什么时候交易、交易多少以及亏损到什么程度退出。

证据边界：该发言是最完整的总路线，但没有公开具体规则、参数、阈值和评估合同。

### [E06] 分钟样本、Label 示例和禁止未来数据

时间：2026-07-27 18:07  
来源定位：`data/organized/Courage/conversations.md:674-676`

> **Courage 18:07**：对，但要区分“表格模型”和“时序模型”。如果用 LightGBM/XGBoost，那么可以把每个“股票 × 分钟时刻”作为一条样本：  
> 样本索引 = `(instrument, datetime)`  
> 特征 = 当前及历史分钟特征 + 已知的日频特征  
> 标签 = 未来 N 分钟收益  
>  
> eg：SH600000，2026-07-27 10:30  
> 分钟特征：`ret_1min ret_5min volume_ratio_20min vwap_bias volatility_30min`  
> 日频特征：昨日涨跌幅、过去5日收益、过去20日波动率、昨日换手率、昨日市值、行业编码  
> 标签：10:31买入，11:01卖出的实际收益  
>  
> Qlib 的数据组织本质上就是以 `(datetime, instrument)` 为索引的二维样本，DataHandlerLP 再负责生成训练和推理数据，分钟级 datetime 可以成为样本粒度。  
>  
> 但有一个关键点：10:30 的样本只能使用 10:30 当时已经知道的数据。所以，日频特征不能直接使用“当天完整日线”。比如在 2026-07-27 10:30 可以使用：2026-07-24 的收盘价、成交量，截至上一交易日计算的 MA20 和日频因子。不能使用：2026-07-27 的收盘价、全天成交量、最高价、最低价，以及收盘后才能计算出来的日频因子。对齐方式通常是把日频特征整体滞后一个交易日，然后广播到次日所有分钟。

证据边界：10:31～11:01 是示例，不等于已冻结的成交价格或 Label 公式。

### [E09] 回归、分类、盈亏比与候选预测目标

时间：2026-07-27 18:25  
来源定位：`data/organized/Courage/conversations.md:743-744`

> **Courage 18:25**：LSTM 训练时不一定要直接设置预期盈亏比，主要看标签怎么设计。如果模型是做回归，标签通常设置为未来 N 分钟的收益率，例如未来 N 分钟收益。模型只负责预测预期收益，止盈、止损和盈亏比放在交易策略层设置。比如模型预测收益超过 0.5% 才买入，止盈 1%，止损 0.5%，对应盈亏比 2:1。  
>  
> 如果模型是做分类，也可以把盈亏比直接融入标签。例如未来一段时间内先上涨 1% 记为买入标签，先下跌 0.5% 记为不买或卖出标签，这种方式类似三重障碍法，相当于训练模型判断止盈和止损哪个先触发。  
>  
> 我更倾向于第一种：模型预测未来收益、上涨概率或者最大上涨空间，交易层再根据手续费、滑点、波动率和市场状态动态设置盈亏比。因为固定盈亏比直接写进标签后，模型会比较依赖当前设定，后续修改止盈止损就需要重新生成标签和训练模型。  
>  
> 另外，盈亏比不能单独看，还要结合胜率。比如盈亏比 2:1，但胜率只有 20%，策略仍然可能亏损。真正需要优化的是扣除手续费和滑点后的期望收益：期望收益 = 胜率 × 平均盈利 − 亏损概率 × 平均亏损。

证据边界：0.5%、1%、2:1 和 20% 都是解释性示例，不是正式参数。

### [E16] horizon、lookback、输入独立性和快慢变量融合

时间：2026-08-10 17:51～18:09  
来源定位：`data/organized/Courage/conversations.md:3718-3747`

> **me 17:51**：您的PatchTST多周期预测一般最长会预测到多久，比如多少分钟或多少个交易日？模型输入又通常回看多长时间，例如过去240、480还是1200分钟？输入窗口必须覆盖最长预测周期吗，还是输入长度和预测长度可以分别设置？不同预测周期是共享同一个输入窗口，还是会使用不同长度的历史窗口？另外输入特征是统一作为多变量序列输入，还是动态分钟特征和日频慢变量分开处理？  
>  
> **Courage 18:05**：最长预测周期  
> 我主要做三天以内的短周期预测，一般不会直接预测几天后的收益，而是拆成多个 horizon，比如 5、15、30、60、120、240、480 分钟，最长覆盖 1～3 个交易日（约 240～800 分钟）。超过三天后，分钟级特征的信息衰减比较明显，一般会考虑切换到日频模型。  
>  
> 输入窗口长度  
> 输入窗口没有固定值，通常根据预测周期通过实验确定。比如预测 5～60 分钟收益，历史回看 240～480 分钟通常比较合适；如果预测 1～3 天，会尝试扩大到 960～1200 分钟甚至更长。  
> 实际训练时会测试不同 lookback window，比如 240、480、960、1200 分钟，通过验证集选择效果最好的窗口。窗口过短可能捕捉不到趋势信息，窗口过长容易引入过期信息和噪声。  
>  
> 输入窗口是否必须覆盖预测周期  
> 不需要。PatchTST 中输入长度和预测长度是两个独立参数。可以使用过去 480 分钟的数据预测未来 60 分钟，也可以使用过去 1200 分钟的数据预测未来 480 分钟。输入窗口不要求一定大于预测窗口，但是预测周期越长，一般需要更长的历史上下文。  
>  
> 不同预测周期是否共享输入窗口  
> 如果采用多 horizon 预测，我一般会共享同一个输入窗口，例如输入过去 1200 分钟，同时预测未来 5、15、30、60、120、240、480 分钟。模型结构上使用共享的 PatchTST backbone 提取历史时序特征，然后针对不同预测周期设计不同的输出 head。  
> 如果实验发现短周期和长周期存在明显差异，也可以拆分窗口，例如：短周期（5～60 分钟）使用 240～480 分钟历史；长周期（120～480 分钟）使用 960～1200 分钟历史。  
>  
> 输入特征如何处理  
> 分钟动态特征和日频慢变量一般不会完全混合处理。分钟级动态特征，例如 OHLCV、成交量、资金流、盘口特征、技术指标等，作为多变量时间序列输入 PatchTST。日频慢变量，例如市值、行业信息、日线趋势、基本面指标等，更倾向于单独编码，通过 MLP 或其他 encoder 提取特征，然后和 PatchTST 输出的分钟级 embedding 做融合。  
> 整体结构类似：  
> 分钟动态序列 → PatchTST Encoder  
> 日频/静态特征 → Feature Encoder  
> 两者 Feature Fusion → 多 horizon prediction heads  
> 差不多是这个样子。  
>

> **Courage 18:09**：不过涉及到参数的修改，最好还是自己调一下，或者设计好baseline让ai输出kpi文档。
